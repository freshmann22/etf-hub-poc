# multi-agent-start — 멀티에이전트 원스톱 실행

## 목적과 범위

사용자가 `/multi-agent-start`를 실행하면:

1. 프로젝트 요구사항(브리프)을 확인·정리하고 실행 계획을 작성해
   **사용자 승인을 받는다** (S1 — 필수 승인 지점).
2. 승인 후 `MULTI_AGENT_WORKFLOW.md`의 **S2~S9를 사용자 추가 개입 없이
   자동으로 진행한다** (아래 "중단 조건"에 해당하는 경우만 예외).
3. 최종 보고서(S10)를 제출하고 **사용자 최종 승인 대기 상태에서 멈춘다.**

이 Skill은 특정 기술 스택이나 프로젝트 종류에 종속되지 않는다.

## 실행 규칙 문서

이 Skill을 실행하면 **가장 먼저 프로젝트 루트의 `MULTI_AGENT_WORKFLOW.md`를
읽는다.** 그 문서가 단계(S1~S10), 담당자, 통과 조건, 오류 처리, 승인 지점의
기준이다. 이 Skill은 그 절차의 실행기이며, 이 문서와 워크플로 문서가
충돌하면 진행을 멈추고 사용자에게 보고한다.
`MULTI_AGENT_WORKFLOW.md`가 없으면 진행하지 말고 사용자에게 보고한다.

## Phase A — 준비와 계획 (S1)

### A1. 실행 전 확인 (전부 통과해야 진행)

1. **Git 저장소 확인** — `git rev-parse --is-inside-work-tree`.
   저장소가 아니면 멈추고 사용자에게 `git init` 여부를 묻는다.
2. **Codex MCP 연결 확인** — `claude mcp list`에서 codex가 Connected인지
   확인한다. 연결되지 않았으면 멈추고 사용자에게 보고한다
   (독립 검증 에이전트 없이 진행하지 않는다).
3. **프로젝트 브리프 존재 확인** — 루트에서 브리프 문서(관례상
   `PROJECT_BRIEF.md`)를 찾는다.

### A2. 프로젝트 브리프 확보

브리프가 **있으면**: 읽고, 아래 5개 항목이 모두 담겨 있는지 점검한다.
빠진 항목은 사용자에게 질문해 보완한다.

브리프가 **없으면**: 사용자에게 다음 5가지를 질문하고, 답변을 바탕으로
`PROJECT_BRIEF.md`를 작성한다.

1. **무엇을 만들 것인지** — 한 문단 이내의 목표
2. **최소 기능** — 번호를 붙인 기능 목록 (각 기능은 검증 가능한 문장으로)
3. **제외 범위** — 하지 않을 것의 명시적 목록
4. **완료 조건** — 무엇이 충족되면 끝났다고 판정하는지
5. **검증 방법** — 자동 테스트 실행 방법과 동작(화면) 확인 방법

답이 모호하면 그대로 기록하지 말고 검증 가능한 형태로 되물어 확정한다.

### A3. 실행 계획 작성

`MULTI_AGENT_WORKFLOW.md`의 S1 산출물 기준으로 계획을 작성해 화면에 보고한다:

- 단계별 작업 분해 (계약 작성 → 구현·테스트 병렬 → 리뷰 → 실행·재작업
  루프 → 동작 검증 → 최종 평가)
- 각 작업의 담당 역할(총괄/구현/검증), 선행조건, 완료조건, 결과물, 검증 방법
- 구현 에이전트와 검증 에이전트의 **파일 경계** (서로소가 되도록 —
  계약 단계에서 파일 단위로 확정한다)
- 이 프로젝트에 맞는 테스트 실행 명령과 동작 검증 방법 제안

### A4. 계획 승인 대기 (필수 정지)

계획을 보고한 뒤 **반드시 사용자 승인을 요청하고 멈춘다.**

- 승인 전에는 Claude 서브에이전트(Agent 도구)도, Codex(MCP)도 호출하지
  않으며, 계약 작성·코드 작성도 시작하지 않는다.
- 승인은 사용자의 명시적 답변으로만 성립한다. 무응답·침묵을 승인으로
  간주하지 않는다.
- 사용자가 조건부 승인·수정 요청을 하면 계획을 보완해 다시 승인을 받는다.

## Phase B — 자동 실행 (S2~S9, 사용자 개입 없음)

계획이 승인되면 아래 흐름을 **중단 조건에 해당하지 않는 한 사용자에게
묻지 않고** 순서대로 진행한다. 각 단계의 상세 규칙(입력·결과물·통과 조건·
작업 규칙)은 `MULTI_AGENT_WORKFLOW.md` §2를 따른다.

1. **계약 작성 (S2)** — Fable이 `CONTRACT.md`를 작성한다. 데이터 스키마,
   함수 시그니처·엣지케이스·에러 문구(문자 그대로 따를 수 있는 수준),
   모듈 방식, **에이전트별 담당 파일 목록(서로소)**, 최소 기능 1:1 대응표를
   확정한다.
2. **구현·테스트 병렬 (S3‖S4)** — Claude Sonnet 서브에이전트(구현, 백그라운드)와
   Codex(테스트 작성, workspace-write)를 병렬로 실행한다. Codex에는 계약
   문서만 전달한다(구현 참조 금지). 완료 시 Fable이 파일 경계·시그니처
   준수를 확인한다.
3. **독립 리뷰 (S5)** — Codex(read-only)가 브리프·계약·구현 파일을 기준으로
   3분류(확인된 문제/잠재 위험/문제 없음) 리뷰를 수행한다.
4. **리뷰 오탐 판정** — Codex의 "확인된 문제"는 **Fable이 지적된 파일을
   직접 읽어 재현 확인한 후에만** 재작업 대상으로 인정한다. 재현 불가
   지적은 근거를 기록하고 기각한다.
5. **테스트 실행 (S6)** — Fable이 직접 실행한다(에이전트 호출 없음).
   결과 원문(전체/통과/실패 수, 실패 테스트명, 오류 메시지)을 기록한다.
6. **실패 원인 판정 (S7)** — 실패 출력의 실제값과 계약 문구를 대조해
   각 실패를 **구현 오류 / 테스트 오류 / 계약 오류**로 귀속한다.
   "실패 = 구현 문제"로 자동 귀속하지 않는다.
7. **부분 재작업 (S8)** — 원 담당 에이전트에게 **실패 단위로 한정된
   범위만** 재작업을 배정한다. 통과 중인 코드·테스트 수정 금지, 상대
   에이전트 파일 접근 금지. 계약 오류면 Fable이 계약을 수정하고 영향
   받는 쪽에 배정한다.
8. **루프** — 테스트 전체 통과까지 5→6→7을 반복한다. 리뷰 지적 처리도
   같은 판정 절차를 따른다. **동일 오류의 재작업이 3회 실패하면 중단
   조건이다** (사용자에게 보고).
9. **동작 검증 (S9)** — Fable이 Playwright 등 프로젝트에 맞는 방법으로
   브리프의 최소 기능 각각 + 대표 오류 경로 + 콘솔 오류를 확인한다.
   실패 발견 시 재현 절차를 기록하고 6의 판정 절차로 회부한다.
10. **최종 보고·승인 대기 (S10)** — 아래 "최종 보고" 형식으로 보고하고
    **사용자 최종 승인 대기 상태에서 멈춘다.**

자동 구간에서 총괄이 스스로 판단해 진행하는 것들 (사용자에게 묻지 않음):
일반적인 구현 선택, 테스트 실패 처리, 리뷰 결과 판정, 비파괴적 파일
생성·수정, 로컬 명령 실행(테스트·로컬 서버·브라우저 검증 포함).

## 중단 조건 (이 경우에만 자동 실행을 멈추고 사용자에게 묻는다)

다음 중 하나라도 해당하면 즉시 해당 작업을 멈추고, 상황·사유·선택지를
사용자에게 보고한 뒤 답변을 기다린다 (`MULTI_AGENT_RUN_LOG.md`에 사유 기록):

1. **추가 비용** — 종량 과금 등 추가 비용 발생 가능성
2. **인증 필요** — API Key 발급·입력, 외부 계정 로그인, 기타 인증
3. **민감 정보 필요** — 개인정보, 비밀번호, 결제정보, 사내 기밀 입력
4. **외부 연결 필요** — 외부 API 호출, 외부 서비스 사용
5. **외부 공개 필요** — 배포, 게시, PR 생성 등
6. **파괴적 변경 필요** — 파일 삭제, git 이력 변경, 대규모 덮어쓰기
7. **계약 확정 불가** — 요구사항 모순으로 계약을 확정할 수 없음
8. **재작업 한도** — 동일 오류에 대한 재작업 3회 실패
9. **MCP 연결 지속 실패** — Codex 호출 실패가 1회 재시도 후에도 지속
   (Codex 몫을 다른 에이전트가 대신 수행하지 않는다 — 독립 검증 무력화 방지)
10. **자원 한도** — 구독 사용량 한도 임박 또는 모델 사용 불가

## 실행 로그 — `MULTI_AGENT_RUN_LOG.md`

Phase B 시작 시 루트에 `MULTI_AGENT_RUN_LOG.md`를 생성하고(이미 있으면
이번 실행 섹션을 추가), **각 단계의 시작과 완료 시점마다** 갱신한다.
기록 항목:

- 단계 번호(S2~S10)와 단계명, 시작·완료 여부
- 담당 에이전트 (Fable / Claude Sonnet / Codex)
- 생성·수정된 파일 목록
- 테스트 결과 (전체/통과/실패 수, 실패 테스트명)
- 재작업 횟수 (실패 건별 귀속 판정 포함)
- 사용자 개입이 발생했다면 그 사유 (위 중단 조건 중 어느 것인지)

로그는 Fable만 기록한다 (서브에이전트·Codex에게 로그 파일 쓰기를
배정하지 않는다).

## 최종 보고 (S10)

자동 구간이 끝나면 다음을 포함한 최종 보고서를 화면에 보고한다:

1. **완료 조건별 판정** — 브리프의 완료 조건 각각에 대한 충족/미충족
2. **테스트 결과** — 최종 실행 결과 (전체/통과/실패)
3. **화면(동작) 검증 결과** — 최소 기능별 통과/실패 표, 콘솔 오류 여부
4. **남은 위험** — 잔존 위험·미검증 가정 목록
5. **에이전트별 작업 횟수** — 호출 횟수, 재작업 횟수 등 정량 기록

보고 후 **사용자의 최종 완료 승인을 요청하고 멈춘다.** 승인 전에는 추가
작업을 하지 않는다.
