# ACCEPTANCE TEST PLAN

## 1. 검증 목적

이번 검증은 실제 ETF 데이터 정확도가 아니라 다음을 확인한다.

- 메인화면 정보 구조가 요구사항대로 구현됐는가?
- 핵심 탐색 인터랙션이 실제 데이터 변경으로 이어지는가?
- 투자권유로 오인될 문구가 없는가?
- 모바일에서 화면이 깨지지 않는가?
- 멀티에이전트 구현과 독립 테스트가 계약대로 분리됐는가?

## 2. 자동 단위 테스트

### 시장 및 정렬 로직

- 상승 탭은 일간 수익률 내림차순이다.
- 하락 탭은 일간 수익률 오름차순이다.
- 거래 급증 탭은 거래대금 증감률 내림차순이다.
- 변동성 확대 탭은 변동성 점수 내림차순이다.
- 동률 정렬 규칙이 일관된다.

### 기간 변경

- 1일, 1주, 1개월 선택에 따라 테마 수익률이 변경된다.
- 기간 변경에 따라 강한 테마와 약한 테마가 재계산된다.
- 활성 기간 상태가 하나만 존재한다.

### 테마 필터

- 테마 선택 시 해당 테마 ETF만 표시된다.
- 존재하지 않는 테마는 빈 결과를 반환한다.
- 중복 ETF가 제거된다.

### 종목→ETF 역검색

- 종목 선택 시 편입 관계가 있는 ETF만 표시된다.
- 편입비중과 순위가 원본 관계 데이터와 일치한다.
- 동일 ETF가 중복 표시되지 않는다.
- 결과 없음 상태가 처리된다.

### 통합 검색

- ETF명, 코드, 종목명, 테마명이 검색된다.
- 부분 일치가 동작한다.
- 앞뒤 공백과 대소문자 차이가 처리된다.
- 빈 검색어와 결과 없음 상태가 처리된다.

### 비교

- 비교 대상 변경 시 모든 비교 지표가 함께 변경된다.
- 동일 ETF 중복 선택이 방지된다.
- 구조 차이 설명이 데이터와 모순되지 않는다.

### 콘텐츠 필터

- 뉴스, 공시, 리서치 필터가 동작한다.
- 필터 결과가 없을 때 빈 상태가 표시된다.

### 바텀시트

- ETF 카드 선택 시 해당 ETF의 정보가 표시된다.
- 닫기 버튼으로 닫힌다.
- 배경 선택 또는 ESC로 닫힌다.
- 다른 ETF를 선택하면 내용이 갱신된다.

### fallback

- 누락된 숫자가 0으로 오인 표시되지 않는다.
- 누락값은 `정보 없음` 또는 `-`로 표시된다.
- 잘못된 참조 ID가 치명적 오류를 만들지 않는다.

## 3. 콘텐츠 정책 테스트

화면 텍스트에 다음 금지 표현이 없어야 한다.

- 추천 ETF
- 지금 사야
- 매수 타이밍
- 매도 타이밍
- 상승 가능성이 높은
- 목표가격
- 목표수익률

실제 설정액 또는 순자산 증감 데이터가 없는 상태에서 다음 표현을 사용하지 않는다.

- 자금 유입
- 돈이 몰렸다
- 자금이 빠져나갔다

가격 변동 배경은 확정적 인과 표현을 피한다.

샘플 데이터 고지 문구가 존재해야 한다.

## 4. DOM 및 접근성 테스트

- 모든 탭과 버튼에 식별 가능한 이름이 있다.
- 활성 상태가 `aria-selected`, `aria-pressed` 또는 동등한 방식으로 표현된다.
- 바텀시트는 dialog 역할과 레이블을 가진다.
- 닫기 버튼이 키보드로 접근 가능하다.
- 검색 입력에 label 또는 접근 가능한 이름이 있다.
- 상승·하락은 색상 외에 부호 또는 텍스트로 구분된다.
- 주요 이미지나 아이콘이 의미를 전달할 경우 대체 텍스트가 있다.

## 5. Playwright 시나리오

### 시나리오 A — 최초 진입

1. 390 × 844 viewport로 접속한다.
2. 제목 `ETF`를 확인한다.
3. 샘플 데이터 고지를 확인한다.
4. 검색창을 확인한다.
5. 시장 요약을 확인한다.
6. 첫 viewport에 히트맵 상단이 보이는지 확인한다.
7. 가로 스크롤이 없는지 확인한다.

### 시나리오 B — 히트맵 기간 전환

1. `오늘`을 확인한다.
2. `1주`를 선택한다.
3. 카드 수익률 또는 순서가 변경되는지 확인한다.
4. `1개월`을 선택한다.
5. 활성 상태가 하나만 존재하는지 확인한다.

### 시나리오 C — ETF 순위 전환

1. 상승 탭을 확인한다.
2. 하락 탭을 선택한다.
3. 첫 ETF와 수익률이 변경되는지 확인한다.
4. 거래 급증 탭을 선택한다.
5. 거래대금 변화 정보가 표시되는지 확인한다.
6. 변동성 확대 탭을 선택한다.

### 시나리오 D — 종목으로 ETF 찾기

1. SK하이닉스 종목 칩을 선택한다.
2. 관련 ETF 결과를 확인한다.
3. 각 결과에서 SK하이닉스 편입비중을 확인한다.
4. 다른 종목을 선택한다.
5. 결과가 변경되는지 확인한다.

### 시나리오 E — ETF 프리뷰

1. ETF 카드를 선택한다.
2. 바텀시트가 열린다.
3. 선택한 ETF명과 주요 정보가 일치한다.
4. 매수·매도 버튼이 없는지 확인한다.
5. 닫기 버튼으로 닫는다.

### 시나리오 F — 비교

1. 비교 테마를 확인한다.
2. 비교 대상 ETF를 변경한다.
3. 구성종목, 순자산, 거래대금, 보수, 수익률이 갱신되는지 확인한다.
4. 우열 또는 추천 문구가 없는지 확인한다.

### 시나리오 G — 콘텐츠

1. 뉴스 필터를 확인한다.
2. 공시 필터로 변경한다.
3. 리서치 필터로 변경한다.
4. 각 유형에 맞는 카드가 표시되는지 확인한다.

### 시나리오 H — 검색

1. `반도체`를 입력한다.
2. 테마와 ETF 결과를 확인한다.
3. `SK하이닉스`를 입력한다.
4. 종목과 관련 ETF 결과를 확인한다.
5. 존재하지 않는 문자열을 입력한다.
6. 결과 없음 상태를 확인한다.

### 시나리오 I — 반응형과 콘솔

다음 viewport에서 검증한다.

- 360 × 800
- 390 × 844
- 430 × 932

확인:

- 전체 가로 스크롤 없음
- 카드 겹침 없음
- 텍스트 치명적 잘림 없음
- 바텀시트가 viewport를 벗어나지 않음
- 콘솔 error 없음
- 미처리 promise rejection 없음

## 6. 완료 판정

다음 조건을 모두 만족해야 완료로 판정한다.

- 자동 테스트 전부 통과
- Playwright 핵심 시나리오 전부 통과
- 치명적 화면 결함 없음
- 콘솔 오류 없음
- 금지 문구 없음
- 샘플 데이터 고지 존재
- 구현 파일과 테스트 파일 소유권 위반 없음
- 독립 리뷰의 유효 지적이 모두 처리되거나 근거와 함께 기각됨
