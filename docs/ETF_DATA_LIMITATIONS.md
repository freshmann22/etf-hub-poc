# ETF 데이터 한계 및 이용조건 체크리스트

실데이터 전환의 공급 구조는 구현했으나, 각 소스의 **이용약관·라이선스·재배포·호출제한·안정성**은
운영 채택 전 별도 확인이 필요하다. 이 문서는 그 미해결 리스크를 정직하게 남긴다.
(`docs/SOURCE_CONTEXT.md §7` — "제공 가능 여부와 라이선스를 별도 검토"와 연결.)

## 1. 공통 원칙

- **데이터를 지어내지 않는다.** 실패/미지원은 `unavailable`/`partial` 로 표기한다.
- **비밀값을 노출하지 않는다.** API 키·시크릿은 로그·응답·오류 메시지에 싣지 않는다(`server/lib/errors.js`,
  provider auth 헤더 주석 참조).
- **임의 호스트로 요청하지 않는다.** `server/lib/http.js` 의 allowlist 로 아웃바운드 호스트를 강제한다.
- **무한 재시도 금지.** 유한 지수 백오프 + 타임아웃 + 응답 크기 상한.

## 2. 소스별 리스크

### 토스증권 Open API (openapi.tossinvest.com) — 실 시세 채널, 실호출 확인됨
- OAuth2 client_credentials → Bearer 토큰(만료 ~24h, 1클라이언트 1토큰: 재발급 시 기존 토큰 무효).
- `/api/v1/prices` 는 **현재가(lastPrice)만** 제공 → 등락률은 `/api/v1/candles`(일봉 전일종가)로 서버가 계산.
  번들 오버레이 시 종목당 캔들 1회(전일종가)를 조회하므로 **최초 로드는 느릴 수 있다**(일 단위 캐시로 완화).
- **사전 신청 대상 단계적 롤아웃 · REST only · rate limit 그룹(MARKET_DATA/CHART)** 존재 → 호출량 관리 필요.
- 제공 범위: 국내(KRX)·미국 현재가/호가/체결/캔들. **구성종목·분배·괴리율·추적오차·순자산은 미제공** →
  이 항목들은 여전히 fixture 이거나 별도 소스가 필요.
- **필요 조치**: 신청 승인·서비스 약관·상업적 이용 조건 확인, 호출한도 모니터링.

### KRX (data.krx.co.kr / openapi.krx.co.kr) — 현재 미가용(인증 방식 불일치)
- **포털 로그인 ID/PW 로는 데이터 API 를 호출할 수 없다.** 공식 KRX Open API 는 로그인 후
  **API 인증키(AUTH_KEY)** 를 별도 발급받아야 한다(현재 미배선 — 인증키 발급 후 구현 필요).
- 본 코드의 krx provider 가 시도하는 인증키 없는 공개 엔드포인트(`bld`)는 **비공식 관례**로,
  최근 로그인/인증 요구·엔드포인트 변경으로 **400 에러가 확인**되었다(불안정).
- hybrid 모드에서는 실패 시 자동으로 mock/다른 provider 로 폴백된다.
- **필요 조치**: 안정 시세가 필요하면 토스증권을 쓰거나, KRX AUTH_KEY 를 발급받아 openapi.krx.co.kr 연동을 구현.

### 증권사 오픈API (broker) — 자격 필요
- 계약·심사·앱키/시크릿·계정 profile·호출한도가 증권사마다 다르다.
- 실시간 시세는 **라이선스/과금** 대상일 수 있고, 지연시세와 구분해 표기해야 한다.
- **필요 조치**: 사용자가 `.env` 에 자격 직접 입력, baseUrl 호스트를 allowlist 에 반영, 지연 여부 명시.

### DART 전자공시 (opendart.fss.or.kr) — 공식 API, 키 필요
- 공식 OpenAPI. **일일 호출한도**·오류코드(예: 020 사용한도 초과) 처리 필요.
- ETF 종목→corp_code 매핑 테이블이 있어야 특정 종목 공시를 정확히 조회한다(현재 최근 공시 제한 조회).
- **필요 조치**: corp_code 매핑 확보, 한도 모니터링.

### 운용사 공식 자료 (issuer) — 다운로드 URL 필요
- 운용사별 구성종목/분배 파일(CSV·PDF) 규격이 제각각 → **운용사별 파서** 필요.
- **필요 조치**: 운용사별 공개 다운로드 URL·포맷 확인, 파서 매핑 구현. 그 전까지 `NOT_SUPPORTED`.

### KIND / SEIBRO (스크래핑) — 기본 비활성
- 공식 API 부재로 **HTML/PDF 스크래핑**이 필요 → 운영 기본 provider 로 채택하지 않는다.
- **robots.txt·이용약관·인증·호출제한·재배포·HTML 구조 변경** 리스크가 크다.
- `KIND_ENABLED` / `SEIBRO_ENABLED` 로만 활성화되며, 활성화해도 파서 구현 전까지 `NOT_SUPPORTED`.
- **필요 조치**: 약관·robots 확인 후에만 파서 구현. 대체로 issuer/공식 소스를 우선한다.

## 3. 화면 번들 오버레이의 한계

- 오버레이는 **종가·등락률(1일)** 등 단위 호환 필드만 실 시세로 교체한다.
- `return1w`/`return1m`·거래대금(단위 상이)·순자산 등은 오버레이하지 않고 fixture 값을 유지한다.
  → 1일 등락은 실데이터, 주간/월간 지표는 샘플이 섞일 수 있으므로 `meta.overlay` 로 커버리지를 표기한다.
- 테마·구성종목 관계·비교셋·시장요약·콘텐츠는 내부 마스터/뉴스 연동 전까지 fixture 스캐폴드.

## 4. 스코프 경계

이 전환은 **데이터 공급 구조**(provider·서비스·API·캐시·폴백)를 마련한 것이며, ETF 상세화면·차트·
변곡점·기여도·개인화·알림은 여전히 범위 밖이다(`docs/POC_SCOPE_MATRIX.md`). 메인화면의 데이터 출처를
fixture 단일에서 "실데이터를 받을 수 있는 구조"로 전환하는 데 초점을 둔다.
