# MULTI-AGENT PROJECT RULES

## 1. 목적

이 문서는 범용 멀티에이전트 워크플로를 ETF 허브 메인화면 PoC에 적용할 때의 프로젝트 전용 규칙을 정의한다.

## 2. 역할

### Fable 5 — 총괄

- 프로젝트 brief 해석
- 최종 서비스 목표와 이번 PoC 범위 구분
- 실행 계획 수립
- 인터페이스 계약 작성
- 구현·테스트 파일 경계 설정
- Claude와 Codex 작업 배정
- 테스트 및 리뷰 결과 판정
- Codex 리뷰 오탐 검증
- 실패 원인 분류
- 부분 재작업 배정
- Playwright 검증
- 최종 완료 판정

### Claude Sonnet 5 — 구현

- 배정된 구현 파일만 생성·수정
- 테스트 파일 수정 금지
- 인터페이스 계약에 따라 UI와 기능 구현
- 구현 결함으로 판정된 부분만 제한적으로 재작업
- 임의로 범위를 확장하지 않음
- 외부 API, 인증, 배포 기능을 추가하지 않음

### Codex — 독립 검증

- 계약 문서만 기준으로 테스트 작성
- 구현에 대한 독립 코드 리뷰
- 요구사항 누락, 논리 오류, 접근성 문제, 테스트 사각지대 탐색
- 구현 파일 수정 금지
- 총괄이 테스트 결함으로 판정한 경우에만 테스트 파일 수정

## 3. 문서 우선순위

1. `PROJECT_BRIEF.md`
2. `INTERFACE_CONTRACT.md`
3. `docs/POC_SCOPE_MATRIX.md`
4. `docs/UX_SCREEN_SPEC.md`
5. `docs/SAMPLE_DATA_SPEC.md`
6. `docs/ACCEPTANCE_TEST_PLAN.md`
7. 범용 `MULTI_AGENT_WORKFLOW.md`

계약 작성 이후 구현과 테스트는 `INTERFACE_CONTRACT.md`를 직접 기준으로 삼는다. 단, 계약이 brief와 충돌하면 Fable이 계약을 수정한다.

## 4. 권장 파일 소유권

실제 파일명은 실행 계획에서 확정한다.

### Claude 소유

- `index.html`
- `src/**`
- `styles/**` 또는 `src/styles/**`
- 애플리케이션용 정적 자산
- 구현 관련 설정 파일

### Codex 소유

- `tests/**`
- 테스트 전용 fixture
- 테스트 설정 파일

### Fable 소유

- `EXECUTION_PLAN.md`
- `INTERFACE_CONTRACT.md`
- `MULTI_AGENT_RUN_LOG.md`
- 계약 및 판정 문서

공용 설정 파일은 Fable이 소유권을 지정한다.

## 5. 병렬 작업 원칙

- Claude와 Codex는 인터페이스 계약이 확정된 뒤 병렬로 작업한다.
- Codex는 Claude 구현을 보지 않고 1차 테스트를 작성한다.
- 구현과 테스트가 동일 파일을 수정하지 않도록 한다.
- 테스트를 통과시키기 위해 구현이 테스트 파일을 수정해서는 안 된다.
- 테스트가 잘못된 경우 Fable이 원인을 판정한 뒤 Codex에만 수정 권한을 부여한다.

## 6. 실패 원인 분류

Fable은 실패를 다음 중 하나로 분류한다.

- 구현 결함
- 테스트 결함
- 계약 결함
- 환경 결함
- 데이터 fixture 결함
- 요구사항 모순
- 리뷰 오탐

판정 근거를 run log에 남긴다.

## 7. 재작업 규칙

- 전체 재작성보다 최소 범위 부분 수정 우선
- 구현 결함은 Claude에 배정
- 테스트 결함은 Codex에 배정
- 계약 결함은 Fable이 계약을 먼저 수정한 뒤 필요한 부분만 재배정
- 동일 오류의 재작업은 최대 3회
- 3회 실패 시 자동 구간 중단 후 사용자에게 보고

## 8. 코드 리뷰 규칙

Codex 리뷰는 다음을 확인한다.

- brief 및 계약 요구사항 누락
- 상태 전환 오류
- 정렬·필터·검색 로직 오류
- 데이터 참조 불일치
- 모바일 레이아웃 위험
- 접근성 문제
- 금지 문구 및 투자권유 오인 가능성
- 외부 통신 또는 불필요한 의존성
- 테스트되지 않은 핵심 분기

Fable은 모든 리뷰 지적을 그대로 수용하지 않는다. 코드와 계약에 근거해 유효성 여부를 판정한다.

## 9. 화면 검증 규칙

Playwright 검증은 자동 테스트 이후 수행한다.

필수:

- 모바일 viewport
- 첫 viewport 구성
- 탭·필터·검색·바텀시트
- 텍스트 잘림
- 전체 가로 스크롤
- 콘솔 오류
- 금지 CTA 부재
- 샘플 데이터 고지

시각적 결함은 스크린샷과 DOM 상태를 함께 확인한다.

## 10. 자동 실행 중단 조건

다음 상황에서만 사용자에게 보고하고 중단한다.

- 추가 비용 또는 종량 과금 가능성
- API Key 필요
- 외부 계정 로그인·인증 필요
- 개인정보, 비밀번호, 결제정보 또는 사내 기밀 필요
- 외부 API 또는 외부 서비스 연결 필요
- 배포, 게시, PR 생성 등 외부 공개 필요
- 파일 삭제, Git 이력 변경 또는 대규모 덮어쓰기 필요
- 요구사항 모순으로 계약 확정 불가
- 동일 오류 재작업 3회 실패
- Codex MCP 연결 실패가 재시도 후에도 지속
- 필요한 모델 사용 불가
- 기존 프로젝트 파일과 충돌

## 11. 범위 확장 금지

다음은 실행 중 임의로 추가하지 않는다.

- ETF 상세화면 전체
- 가격 차트
- 실시간 데이터
- 외부 API
- 로그인
- 계좌 연동
- 주문 기능
- 추천 알고리즘
- 서버·데이터베이스
- 자연어 AI 기능
- 배포 파이프라인

필요성을 발견하면 구현하지 말고 후속 제안으로만 기록한다.
