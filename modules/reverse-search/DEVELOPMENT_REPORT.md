# 역검색(Reverse Search) 모듈 — 개발 배경 및 과정 리포트

> 이 문서는 파트너 측(디자인/UI + 뉴스·공시 브리핑 담당)의 AI 에이전트가 이 모듈을 빠르게 이해하고
> 자신의 작업(디자인 이식, Explore 통합)에 필요한 판단을 내릴 수 있도록 작성했습니다.
> 코드 자체의 상세 계약은 [`README.md`](./README.md)를 보고, 이 문서는 **왜 이렇게 만들었는지**를 설명합니다.

## 1. 전체 프로젝트 맥락

증권사 모바일 앱의 ETF 조회/분석 도구를 만들고 있습니다. 목적은 ETF 투자고객(투자전/투자중/매도매수
3단계)이 최선의 종목을 선택하도록 돕는 것이고, 화면은 대쉬보드 구조입니다.

- **검색 영역**(전략/섹터 구분) → **종목 열거 영역**(선택된 조건에 맞는 ETF 나열) → **종목 상세 영역**
  (수익률/보수/구성종목 등).
- 개발은 두 사람이 병렬로 진행합니다.
  - **파트너**: 전체 화면 윤곽(폰트/UI/디자인), 뉴스 브리핑(섹터 뉴스 20자 요약, 공시 요약).
  - **본인(이 리포지토리의 요청자)**: **역검색** 파트.
  - 본인이 만든 것을 파트너에게 넘기면, 파트너가 자신의 디자인에 녹여 붙이는 흐름입니다. 이 리포지토리
    (`etf-hub-poc`)는 그 이전 단계까지의 공용 PoC이고, `docs/COLLABORATION_HANDOFF.md`에 명시된 대로
    신규 기능은 `modules/<module-name>/` 아래 독립 모듈로 개발한 뒤 별도 PR로 리뷰·통합합니다.

## 2. 역검색이 해결하려는 문제

일반 키워드 검색으로는 안 되는, **의도 기반** 질의입니다.

- "삼성전자가 가장 많이 들어간 ETF 뭐야?"
- "현대차 비중이 가장 높은 ETF는?"
- "거래량 많은 ETF를 순서로 나열해줘"

요청자의 파트너가 국내 상장 ETF 전체에 이미 태그(섹터/전략/배당 등)를 달아뒀고, 이 모듈은 그 태그와
기존 데이터를 활용해 자연어 질의를 해석하고 종목을 나열합니다.

### 요청자가 명시한 필수 요건

1. 최종 결과는 **주어진 ETF 종목 안에서만** 나열한다(없는 데이터를 만들어내지 않는다).
2. 각 종목마다 **입력 의도와의 유사성 근거**를 붙인다(예: "삼성전자 비중 33.7%" 같은 정량적 문구).
3. 유사성이 없거나 희박하면, 그래도 가장 가까운 종목을 보여주되 **"근거가 약해서 이렇게 보여준다"는
   사실을 30자 내외 문구로 고지**한다 — 조용히 틀린 답을 내지 않는다.

## 3. 개발 중 확인이 필요했던 지점과 결정 과정

로직을 짜기 전에, 코드베이스를 먼저 실사(existing fixtures 조사)해서 실제로 쓸 수 있는 데이터가
무엇인지 확인했고, 그 결과를 바탕으로 요청자와 아래 항목들을 하나씩 확정했습니다. (판단이 필요한
지점마다 먼저 묻고, 답변을 받은 뒤 진행하는 방식으로 작업했습니다.)

| 결정 사항 | 선택된 안 | 이유/맥락 |
|---|---|---|
| 자연어 질의 해석 방식 | **PoC 데모용 — 하드코딩된 규칙/사전**(Claude가 이번 세션에서 직접 설계) | 실시간 LLM API 호출(서버가 매 요청마다 Anthropic API 호출)은 `.env`에 API 키 등록·요청당 비용/지연이 발생해 PoC 단계에는 과함. 다만 `nlu.js`의 반환 계약(`{intent, ...payload}`)만 유지하면 나중에 실제 LLM 해석으로 무중단 교체 가능하도록 분리해서 설계함 |
| 종목 비중 질의의 데이터 범위 | 구성종목 데이터가 있는 **427개 ETF 안에서만** 검색 + 안내 문구 | 전체 유니버스는 1,141개지만, top-10 구성종목 데이터(`etf-holdings.json`)는 427개까지만 존재. 나머지 714개는 애초에 응답할 근거 데이터가 없어 정직하게 커버리지를 명시하기로 함 |
| 시황(거래량 등) 정렬 질의의 범위 | **포함하되 커버리지 있는 것만**, 나머지는 "데이터 없음" 명시 | `/api/bundle` 시황 데이터는 큐레이션된 24개 종목 + Toss 실시간 연동 종목 정도만 실값이 있음. 전체 1,141개 기준으로는 정확히 응답할 수 없어 부분 응답 + 커버리지 고지로 처리 |
| 종목명 사전(별칭/오타 매핑) | **Claude가 직접 구축**(홀딩스 데이터에서 추출) | 별도 사전 파일이 프로젝트에 없었음. `etf-holdings.json`의 427개 ETF 구성종목에서 종목명 538개를 추출해 정본 사전으로 쓰고, "삼전"→"삼성전자" 같은 소수의 콜로퀴얼 별칭만 수동으로 보강 |

## 4. 아키텍처

```
modules/reverse-search/
  index.html        # 독립 실행 진입점(390px, http 서빙 필요)
  src/dictionary.js  # 태그 동의어(56개 태그) · 종목 별칭 · 정렬지표 사전
  src/text.js        # 텍스트 정규화
  src/nlu.js         # 질의 → intent 파서(순수 함수)
  src/adapters.js    # 기존 데이터 read-only fetch + 인덱스 구축
  src/ranker.js      # intent별 상위 10개 랭킹 + 근거 생성(순수 함수)
  src/app.js         # DOM 와이어링
  src/styles.css     # 모듈 전용 스타일
  tests/*.test.mjs    # 단위테스트
```

### 데이터 흐름

이 모듈은 **서버를 전혀 건드리지 않습니다.** `server/index.js`가 저장소 루트를 그대로 정적 서빙하기
때문에, 아래 세 경로를 그냥 fetch합니다.

| 경로 | 용도 | 커버리지 |
|---|---|---|
| `/data/tagging/etf-filter-map.json` | 태그 매칭(반도체/고배당/레버리지 등) | ETF 1,141개 전체 |
| `/data/tagging/etf-universe-index-names.json` | 표시용 코드→이름 마스터 | ETF 1,147개 |
| `/public/data/etf-holdings.json` | 종목 비중 매칭 + 종목명 사전 소스 | ETF 427개(top-10 구성종목) |
| `/api/bundle` | 시황 정렬(거래대금/수익률/변동성/보수) | 큐레이션 24개 + 실시간 연동 종목만 실값 |

### 질의 해석 → intent 4종

`src/nlu.js`의 `parseQuery(raw, stockNameIndex)`가 다음 중 하나로 분류합니다.

- `STOCK_WEIGHT` — 종목명이 인식되면(별칭 포함) 최우선 적용. 홀딩스 427개 안에서 비중 내림차순.
- `TAG_MATCH` — 섹터/전략/배당 키워드 인식 시. 여러 키워드가 있으면 AND로 거르고, AND로 0건이면
  OR로 완화한 뒤 "조건을 모두 만족하는 ETF가 없어 가장 가까운 결과를 보여드려요"라고 고지(요건 3 구현).
- `MARKET_SORT` — 거래량/수익률/변동성/보수 등 정렬 키워드 인식 시.
- `COMPOSITE` — 태그 키워드 + 정렬 키워드가 함께 인식되면(예: "반도체 중에서 거래량 많은").
- 아무것도 인식하지 못하면 거래대금 상위 기본값을 보여주고 "의도를 파악하지 못했다"고 고지.

모든 경로가 근거 문구를 30자 내외로 붙입니다(예: `SK하이닉스 비중 30.2%`, `고배당 태그 매칭(신뢰도 65%)`).

## 6. 파트너/파트너 AI가 알아야 할 것

- **이 모듈은 독립 실행체입니다.** `etf-explore.html`/`explore.js`/`explore.css`를 import하거나
  그 DOM에 의존하지 않습니다. 디자인을 입히려면 `src/app.js`의 렌더링 부분(`renderResults`)과
  `src/styles.css`만 교체/이식하면 되고, `nlu.js`/`ranker.js`/`adapters.js`(로직·데이터 계층)는
  그대로 재사용 가능합니다.
- **태그/홀딩스 원본 데이터는 이 모듈이 수정하지 않습니다.** 읽기 전용 fetch만 합니다
  (`data/tagging/**`, `config/etf-tagging/**`, `public/data/etf-holdings.json`은 파트너의 파이프라인
  산출물이거나 기존 CSV 파이프라인 산출물이며 그대로 소비만 함).
- **Explore 화면 통합은 이 PR의 범위가 아닙니다.** `docs/COLLABORATION_HANDOFF.md` 절차대로, 이 모듈
  PR이 승인되면 baseline에 머지되고, 실제 화면에 붙이는 작업은 별도의
  `feat/integrate-reverse-search` PR에서 진행합니다.
- **알려진 한계**(README에도 기재): 자연어 해석이 지금은 규칙/사전 기반(라이브 LLM 아님), 종목 비중
  질의는 427개 ETF로 제한, 시황 정렬은 커버리지가 좁음. 이 세 가지는 각각 별도 확장 작업이 필요합니다.
