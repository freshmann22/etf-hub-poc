일시: 2026-07-14. 목적: 실제로 데이터를 가져올 수 있는지, 그리고 API/로그인이 필요한지
**개인 사용 목적**으로 명확히 확인. 이 문서는 점검 결과만 기록하며, 운영 파이프라인/파서는
**아직 만들지 않았다**(사용자 지시).

## 상세 — 확인된 두 소스

### 1) KODEX / 삼성자산운용
- **요청**: `GET https://m.samsungfund.com/excel_pdf.do?fId=2ETF01&gijunYMD=20260713`
- `fId`는 KRX 종목코드(069500)가 아니라 삼성자산운용 내부 펀드코드(`2ETF01`) — **종목코드→fId 매핑표가 별도로 필요**(상품 목록 페이지에서 확보 가능해 보이나 이번엔 미확인).
- **로그인/API키: 불필요.** 익명 GET 한 번으로 200행 전체(현금성 자산 포함) 응답, HTTP 200.
- 응답은 legacy `.xls`(OLE2 바이너리, CODEPAGE 레코드는 1252로 잘못 표기돼 있으나 `xlrd`로 열면 실제 문자열은 정상 UTF 처리됨 — **최초 터미널 출력에서 깨져 보였던 것은 실제 데이터 손상이 아니라 콘솔 인코딩 표시 문제였음**, 파일로 저장 후 재확인하여 정정).
- 컬럼: 번호/종목명/ISIN/종목코드/수량/비중(%)/평가금액/전일종가/등락.
- raw: `raw/2026-07-14/amc-feasibility/kodex_069500_20260713.xls`

### 2) TIGER / 미래에셋자산운용
- **요청**: `POST https://investments.miraeasset.com/tigeretf/ko/reference/pdf-status-list.ajax`
  body: `pageIndex=1&firstIndex=0&listCnt=300&ksdFund=KR7102110004&jongName=TIGER 200`
- `ksdFund`는 ETF의 **표준 ISIN**(`KR` + 7102110004 형태) — ISIN은 KRX 종목코드로부터 규칙적으로 구성 가능한 값이라 매핑 부담이 KODEX보다 적을 가능성.
- **로그인/API키: 불필요.** `상품별 자료조회` 공개 페이지에서 버튼 클릭으로 트리거되는 내부 AJAX를 그대로 재현.
- 응답 헤더가 `charset=UTF-8`로 정확히 명시되어 있고 실제로도 유효한 UTF-8. `listCnt`를 늘리면(200 지정 시) **한 번의 요청으로 전종목(200개, 현금 포함)** 을 받는다 — 응답에 `data-tot-cnt="200"`로 총 개수도 명시됨.
- 컬럼: 순번/종목코드/종목명/수량/평가금액/비중(%)/전일대비.
- raw: `raw/2026-07-14/amc-feasibility/tiger_102110_pdf.html`

## 확인 필요/미완료 항목 (사실만 기록, 추정하지 않음)

- **다른 운용사**(KBSTAR=KB자산운용, ACE=한국투자신탁운용, SOL=신한자산운용, HANARO=NH-Amundi,
  KOSEF=키움투자자산운용 등)는 이번에 점검하지 않았다. KODEX·TIGER 둘 다 로그인 없이 성공했다는
  점에서 "운용사 홈페이지에 매일 PDF를 공시한다"는 패턴 자체는 자본시장법상 의무이므로 나머지도
  유사할 가능성이 높지만, **URL/파라미터 구조는 운용사마다 다르므로 각각 확인이 필요**하다.
- **종목코드 → 운용사별 내부 ID 매핑**을 어디서 일괄로 얻을 수 있는지는 확인하지 않았다
  (KODEX는 `fId`, TIGER는 ISIN). 상품 목록 페이지(`list.do` 류)를 크롤링하면 얻을 수 있을 것으로
  보이나 실측하지 않았다.
- SEIBro가 TOP10을 넘는 전체 구성종목 화면을 제공하는지는 이번 점검에서 확정하지 못했다(메뉴
  트리를 얕게만 탐색함).
- SEIBro 오픈플랫폼, ETF CHECK, 다음금융, 금융투자협회는 존재 확인 수준이며 실제 데이터 접근
  가능 여부는 미확인 상태로 남겨둔다.

## 결론

**"API도, 로그인도 필요 없이 가져올 수 있는 소스가 최소 2곳(KODEX, TIGER) 실제로 확인됐다.**
두 곳 모두 전 종목(200개, 현금 포함) 구성내역을 단일 익명 HTTP 요청으로 받을 수 있다. 남은 일은
(1) 종목코드→운용사 내부ID 매핑표 확보, (2) 나머지 운용사 동일 패턴 확인, (3) 공통 스키마
(`schemas/etf-holdings.schema.json`) 매핑 — 이며, 사용자 지시대로 **아직 실제 수집/구현은
하지 않았다.**
